# AGENTS.MD — контекст NeuroTranslate

## Назначение проекта

NeuroTranslate — учебный Android-проект офлайн-переводчика. Пользователь скачивает языковой пакет один раз, затем переводит без сети. Основной объём проекта — MVP для русского и английского языков: RU→EN и EN→RU. Это прототип, не production-сервис.

Сейчас репозиторий содержит начальный Android-проект: один модуль `app`, пакет приложения `org.school.neurotranslate`, `minSdk 24`; Git-репозиторий пока не инициализирован. Не описывай запланированные функции как существующие, пока их нет в коде.

## Целевой MVP

- Kotlin, один Android-модуль, Jetpack Compose и MVVM/однонаправленный поток состояния. Разделяй код по пакетам и держи UI зависимым от контрактов, а не от ONNX или файловой системы напрямую.
- Локальный перевод Marian ONNX для обеих языковых пар, каталог моделей, установка/удаление пакета и экран перевода.
- Магазин языков показывает фактический размер пакетов и раздельные показатели: память активной модели (PSS) и место на диске для установленных пакетов.
- Загрузка сообщает прогресс, поддерживает отмену и возобновление, где сервер это позволяет. После установки проверяй целостность файлов и не активируй частично установленную модель.
- MVP использует greedy-декодирование. Beam search, аккаунты, облачный перевод, iOS, история, TTS/STT, дополнительные пары (например RU→DE и EN→FR) и production-аналитика вне текущего MVP.

## Архитектурные границы

Целевые контракты: `TranslationEngine`, `ModelRepository`, `DownloadService` и `Tokenizer`; ожидаемые реализации из концепта — `MarianEngine`, `FileSystemModelRepository`, `UidtDownloadService` и `MarianTokenizer`. Сохраняй эти границы, адаптируя имена и детали к уже существующему коду.

`TranslationService` — единый владелец активной ONNX-сессии и последовательности операций. Сериализуй перевод, переключение модели и удаление активной модели через `Mutex` или эквивалент. При удалении активной модели сначала освободи сессию, затем удаляй файлы. Не используй временные задержки как замену синхронизации.

Закрывай ONNX-сессии и все тензоры явно (`close()` / `use {}`), включая пути ошибок и отмены. Нативная память ONNX не освобождается одним лишь Java GC. Проверяй жизненный цикл повторными загрузками и закрытиями на целевом устройстве.

## Модели и точность контрактов

- Используй закреплённые commit SHA источников Xenova/Hugging Face; не полагайся на плавающую ветку `main`.
- До фиксации каждой модели проверь фактический состав файлов, размеры, SHA-256, `config.json`/`generation_config.json`, имена и формы ONNX-входов/выходов и opset. Записывай проверенные значения в каталог/манифест; не копируй примерные идентификаторы из концепта как факт.
- SHA-256 ожидаемых файлов задаётся доверенным каталогом приложения. Сверяй его при установке; манифест, пришедший вместе с загрузкой, сам по себе не является доверенным источником хешей.
- У Marian decoder обязательны три входа: `encoder_attention_mask`, `input_ids`, `encoder_hidden_states`. Спец-ID (`decoder_start_token_id`, `eos_token_id`, `pad_token_id`) берутся из конфигурации конкретной закреплённой модели.
- Завершай greedy-цикл реальным выходом по EOS и ограничивай длину генерации проверенным значением.
- Эталон токенизации — `MarianTokenizer` Hugging Face для той же модели. `tokenizer.json` нельзя считать корректным только по факту наличия: сверяй токенизацию, включая нормализацию, dummy prefix, code points и обработку специальных токенов. Проверь, требуются ли разные source/target SentencePiece-модели.

## Загрузка и установка

Храни незавершённые загрузки во временном каталоге. Проверяй свободное место до загрузки, статус `206 Partial Content`, `Content-Range` и `ETag`/`Last-Modified` при докачке. Если сервер не поддерживает Range или валидатор изменился, начинай загрузку с нуля. После полной загрузки сверяй SHA-256, записывай манифест, валидируй модель и только затем атомарно перемещай временный каталог в каталог установленной модели. Удаляй остатки незавершённой установки при старте/восстановлении.

Для пользовательских загрузок целевой план: UIDT JobScheduler на Android 14+ (API 34+), foreground service с типом `dataSync` на API 26–33. Учитывай ограничения целевых Android API и проверяй требования SDK/manifest для фактической версии проекта; не делай вывод о совместимости только по плану.

## Память и измерения

Около 117 МБ на пакет и 300 МБ PSS — ориентиры из концепта, а не обещанные характеристики. Размер пакета уточняется по закреплённой ревизии; пиковый PSS и latency нужно измерять на устройстве/эмуляторе и указывать с условиями замера. Разделяй память активной модели и место файлов на диске. Если ориентир 300 МБ превышен, сообщай фактическое значение и исследуй maxLength, утечки и кэш; не подгоняй результаты.

## План проверки и качество

Перед реализацией модели проверь ONNX-контракт и конфигурацию. Для ключевых изменений план концепта предусматривает: проверку ONNX-прогона, сверку 100 фраз токенизатора с HF MarianTokenizer на каждую пару, отмену/докачку/ошибки SHA и не менее 10 циклов загрузки/закрытия для поиска роста памяти. Проверяй сценарии на целевом API и слабом устройстве, когда это доступно. В README и отчётах указывай, что реально проверено, а что осталось целью или ограничением.
