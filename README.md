# NeuroTranslate

Учебный Android-проект офлайн-переводчика. Цель — переводить текст между русским и английским локально после установки языковых пакетов.

Готовы базовые Compose-экраны, переходы, Marian ONNX engine и сервис, сериализующий операции с моделью. Каталог моделей подключён к файловому хранилищу пакетов и загрузчику с SHA-256, отменой и возобновлением.

## Текущий план

- Приложение на Kotlin, один модуль `app`, минимальная версия Android — API 24.
- Целевые языковые направления MVP: RU → EN и EN → RU.
- Базовые экраны перевода, каталога моделей и настроек; состояние экранов хранится во ViewModel.
- ONNX Runtime Mobile закреплён на версии 1.31.0. Engine принимает token IDs и локальные файлы модели, проверяет SHA-256, запускает encoder и greedy decoder с остановкой по EOS.
- `TranslationService` сериализует активацию, генерацию, удаление и закрытие engine. `FileSystemModelRepository` хранит установленные пакеты и staging-каталоги во внутреннем хранилище приложения; установка завершается атомарным переименованием после проверки файлов и ONNX-графов.
- Для закреплённых моделей проверены отдельные `source.spm` и `target.spm`; эталонный набор Hugging Face MarianTokenizer содержит 100 исходных и 100 целевых фраз на каждое направление. Android-реализация SentencePiece и её parity-проверка ещё не подключены.
- Каталог показывает проверенный размер пакета и доступные действия установки, отмены и удаления. Загрузчик проверяет SHA-256, поддерживает HTTP Range/If-Range при совпадении Content-Range и ETag/Last-Modified, проверяет свободное место и не устанавливает неполный пакет.
- Загрузка запускается через UIDT JobScheduler на API 34+ и через foreground service `dataSync` на API 24–33. Незавершённые файлы и валидаторы остаются в staging-каталоге для возобновления после отмены или остановки задания.
- Файлы весов моделей не хранятся в Git. Закреплённые ревизии, размеры и контрольные суммы ONNX-файлов находятся в каталоге моделей.

## Требования для сборки

- Android Studio с JDK 17.
- Android SDK Platform 37 и Android SDK Build-Tools 36.0.0.
- Gradle Wrapper 9.6.0 (скачивается wrapper при первом запуске, если его ещё нет в локальном кэше).

Версии проекта: Android Gradle Plugin 9.4.1, `compileSdk = 37`, `targetSdk = 37`, `minSdk = 24`. Сборка AGP 9.4 требует Gradle 9.6.0 и JDK 17.

### Открыть в Android Studio

1. Открой папку проекта.
2. Установи Android SDK Platform 37 и Build-Tools 36.0.0 через SDK Manager, если они ещё не установлены.
3. Выбери JDK 17 для Gradle и выполни Gradle Sync.

### Собрать APK из командной строки

Windows PowerShell:

```powershell
./gradlew.bat assembleDebug
```

Linux/macOS:

```bash
./gradlew assembleDebug
```

Локальный `local.properties`, каталоги сборки, кэши и скачанные веса не должны попадать в Git.

## Статус

Экран перевода пока не подключён к engine: Android-токенизатор и интеграция строкового ввода с сервисом ещё не реализованы. Настройки темы и длины результата сохраняются, но ограничение длины ещё не управляет переводом. Загрузчик не проверялся сквозной загрузкой с Hugging Face и на устройстве. `testDebugUnitTest` проходит, Android instrumentation tests скомпилированы, но не запускались: подключённого эмулятора нет. Результаты замеров и проверок следует добавлять сюда только после фактического выполнения.

## Модели (проверка дня 3)

Закреплены направления EN → RU и RU → EN на полных ревизиях Helsinki-NLP и их ONNX-конверсий Xenova. Лицензии исходных моделей различаются: EN → RU — Apache-2.0, RU → EN — CC-BY-4.0. Идентификаторы, размеры, SHA-256, входы/выходы, типы и opset выбранных QInt8 ONNX файлов записаны в [каталоге моделей](app/src/main/assets/models/catalog.json). Каждый комплект encoder+decoder содержит 110,189,320 байт ONNX-данных (около 105.1 MiB), без токенизатора.

## ONNX Runtime (день 4)

`MarianOnnxEngine` загружает проверенные локальные encoder/decoder файлы, проверяет входные имена графов и выполняет greedy-генерацию по токенизированному входу. Модель и все тензоры закрываются явно. Для EN → RU структура графов, хеши и контракт подтверждены на закреплённых файлах; запуск генерации на Android-устройстве ещё не проверен. Проверка токенизатора и соединение движка с экраном остаются следующими этапами.

## Токенизатор (день 5 — подготовлены исходники и эталон)

Для Xenova-ревизий обеих моделей проверены реальные `source.spm`/`target.spm`: направления используют разные файлы SentencePiece, причём файлы меняются местами между RU → EN и EN → RU. Их размеры и SHA-256 записаны в каталоге. [Эталонный набор](app/src/test/resources/marian-tokenizer-reference.json) сгенерирован `MarianTokenizer` из Transformers 4.41.2 и содержит 100 пар source/target примеров для каждого направления.

Android-движок SentencePiece пока не реализован, поэтому совпадение Kotlin-токенизатора с эталоном ещё не проверялось. DJL SentencePiece не предоставляет готовый Android native runtime для текущей конфигурации API, а проектный SDK сейчас не содержит Android NDK. День 5 остаётся незавершённым до выбора и проверки работоспособной Android-реализации.

## Сервис перевода (день 6)

`TranslationService` владеет единственным `TranslationEngine` и последовательно выполняет активацию модели, перевод по token IDs, удаление модели и закрытие. При удалении активной модели engine закрывается до вызова репозитория. Ошибки и отмена переключения очищают возможную частично активированную сессию.

## Каталог и загрузка моделей (день 7)

`ModelCatalog` читает закреплённые ревизии, размеры и SHA-256 из `assets/models/catalog.json`. `ResumableModelDownloadService` скачивает ONNX и SentencePiece-файлы во временный каталог, сверяет размер и хеш, проверяет имена входов/выходов encoder/decoder, записывает локальный манифест и только после этого перемещает пакет в установленный каталог атомарным переименованием. Докачка разрешается только при HTTP 206, правильном `Content-Range` и совпадении сохранённого ETag либо Last-Modified; иначе загрузка начинается заново. Экран каталога показывает размер пакета, прогресс и действия отмены/удаления.

Полная загрузка моделей, проверка отмены/докачки на сервере и установка на устройстве не выполнялись. Сборка `compileDebugKotlin` и `assembleDebug` теперь проходит, однако установить приложение на устройство не удалось проверить: `adb devices -l` не обнаружил подключённых устройств или эмуляторов.

## Совместимость фоновой загрузки (день 8)

Для API 34+ каталог ставит user-initiated data transfer job (UIDT), передаёт оценку размера пакета и обновляет системное уведомление через `JobService`. Для API 24–33 используется foreground service с типом `dataSync` там, где он поддерживается. При отмене или остановке задания корутина прекращает сетевой цикл; `.part` и валидаторы остаются на диске, чтобы следующая попытка могла безопасно продолжить передачу.

В manifest объявлены `RUN_USER_INITIATED_JOBS`, `FOREGROUND_SERVICE` и `FOREGROUND_SERVICE_DATA_SYNC`; оба сервиса не экспортируются. `dataSync` service не запускается на API 34+, поэтому ограничения времени API 35+ обходятся использованием UIDT, а не увеличением таймаута. Kotlin compile и сборка debug APK прошли, manifest обработан Gradle. Запуск на эмуляторах API 24–36 не проверен: `adb devices -l` не обнаружил подключённых устройств.

## Настройки и ключевые тесты (день 9)

Настройки темы и максимальной длины результата переведены на Preferences DataStore; размер результата округляется с шагом 16 и ограничен диапазоном 64–400. Добавлены unit-тесты для восстановления настроек, нормализации длины и гарантий `TranslationService` (закрытие модели до удаления файлов, очистка после ошибки активации, сериализация перевода и удаления).

`testDebugUnitTest` проходит: проверяются границы HTTP 206/Content-Range/ETag/Last-Modified, размер и SHA-256 файла, сериализация операций модели и ограничения настроек. `compileDebugAndroidTestKotlin` также проходит; DataStore persistence test оставлен для запуска на Android. Instrumented/UI проверки не запускались, так как эмулятор не подключён. Сквозные сетевые ошибки/докачка и повторные циклы ONNX на устройстве остаются непроверенными.
